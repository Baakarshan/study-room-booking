# 文艺奶龙队开题汇报稿

我们是文艺奶龙队，我们的课题是自习室座位预约系统。

这个项目主要解决学生找座难、空位不清楚、座位被占用后无法及时释放的问题。我们希望做出一个前后端分离、流程完整、方便演示的管理平台，让管理员能维护自习室和座位，让学生能完成预约、签到和使用闭环。

系统分成四块：基础信息管理、学生预约、座位管控和数据报表。

基础信息管理主要维护校区、楼栋、楼层、自习室和座位。学生预约负责筛选自习室、查看座位状态、提交预约。座位管控处理签到、超时释放、爽约和黑名单。数据报表展示座位热力图、使用率和热门时段。

我们小组按职责分工推进。

前端同学主要负责页面布局、预约流程展示和接口对接。后端同学负责基础信息、预约、签到释放等核心接口。部署同学负责环境、数据库、Git 仓库和最终服务器部署。测试与文档同学负责演示数据、主流程测试、功能截图和答辩材料。

后续开发会按模块推进，尽量避免多人同时修改同一批核心文件。

目前我们已经完成了技术栈确认、GitHub 仓库初始化和基础脚手架搭建，数据库表设计和前后端页面正在推进。

接下来会进入本地联调和主流程测试。我们现在最关注的是接口稳定和主流程跑通。

核心流程可以分成三条：

第一条是管理员录入自习室。管理员先录入校区、楼栋、楼层和自习室，再根据行列数批量生成座位。

第二条是学生预约与签到。学生进入系统后筛选自习室，查看座位状态，选择空闲座位并设置预约时间。系统会检查时间冲突、座位状态和学生限制，通过后生成预约。

第三条是座位释放规则。预约开始后，学生需要在 15 分钟内签到。签到成功后，座位进入使用中。如果没有签到，系统会通过定时任务标记爽约并释放座位。爽约达到 3 次后，学生进入黑名单。

我们当前已经完成项目基础准备，分工明确，项目已经进入开发阶段。

下一阶段重点是让数据库和后端接口尽快稳定，让前端完成预约主流程页面，并让测试尽早介入，形成反馈闭环。

我们的开发策略是先完成可演示闭环，再补充异常处理，最后打磨部署和文档。以上就是我们的开题汇报，谢谢老师。
