## 目标

测试重点放在演示会失败的地方：空间数据建不起来、预约冲突没拦住、签到和释放不生效、黑名单没限制、报表没数据、学生看到管理员菜单。

测试不追求复杂覆盖率。每个模块合并前要证明主链路可用，关键边界没有明显缺口。

## 模块验收

| 模块 | 最低验收 |
| --- | --- |
| infra | MySQL 和 Redis 可启动，`admin`、`student01`、`student02` 可登录，菜单权限分开 |
| base-info | 能按校区、楼栋、楼层、自习室、座位建模，批量生成座位正确 |
| reservation | 同一座位重叠时间不能重复预约，学生当天次数限制生效 |
| control | 15 分钟内可签到，超时任务能标记爽约并释放座位 |
| report | 热力图、日均使用率、热门时段能用演示数据复现 |

## 主流程

管理员流程：

1. `admin` 登录。
2. 新增校区、楼栋、楼层。
3. 新增自习室，设置开放时间、关闭时间、行数、列数。
4. 批量生成座位。
5. 查看座位列表和座位图。

学生流程：

1. `student01` 登录。
2. 筛选自习室。
3. 选择空闲座位和起止时间。
4. 提交预约。
5. 在我的预约中看到 `pending_checkin`。
6. 签到后状态变为 `in_use`。

冲突流程：

1. `student01` 预约某座位。
2. `student02` 预约同座位重叠时间。
3. 系统拒绝第二次预约。

## 边界条件

预约：

- 开始时间晚于结束时间时失败。
- 预约时间超出开放时间时失败。
- 停用座位不能预约。
- 黑名单学生不能预约。
- 同一学生同一天超过 1 次预约时失败。
- 同一学生不能在重叠时间预约不同座位。

取消与签到：

- 预约开始前可以取消。
- 预约开始后普通学生不能取消。
- 不能签到别人的预约。
- 已取消、已爽约、已完成预约不能签到。

超时释放：

- 超过 `check_deadline` 的 `pending_checkin` 变为 `no_show`。
- 写入 `seatflow_violation_record`。
- 学生爽约次数增加。
- 满 3 次后黑名单生效。

报表和权限：

- 热力图随日期范围变化。
- 日均使用率不统计停用座位。
- 热门时段口径固定。
- 学生看不到基础信息、黑名单、报表和系统管理菜单。
- 学生不能调用管理员接口。

## Playwright

Playwright 是测试工具链，不是服务器运行依赖。当前使用 4 个串行场景，数据库每次可重复重置：

| 脚本 | 覆盖 |
| --- | --- |
| 管理员空间与报表 | 创建校区并验证预约管理和报表图表 |
| 学生预约 | 页面预约、查看记录并取消 |
| 签到完成 | 页面签到、提前结束和 Quartz 自动完成 |
| 冲突与信用 | 座位冲突、接口 403、三次爽约、拉黑和解除恢复 |

运行 `cd seatflow-ui && npm run smoke` 可启动独立后端、前端和 Playwright。数据库名必须包含 `smoke` 或 `test`，否则重置脚本直接退出。预约时间、每日限次和状态枚举等细规则同时由 Service 单元测试覆盖。

## 部署冒烟

1. Docker Compose 启动 MySQL 和 Redis。
2. 后端启动成功。
3. 前端启动或 Nginx 部署成功。
4. `admin` 能登录。
5. `student01` 能登录。
6. 能完成一条预约流程。
7. 报表页面能看到演示数据。

## 合并要求

每个模块合并前提交：

- 页面或接口说明。
- SQL 草案或无需 SQL 的说明。
- 自测记录。
- 已知限制。

infra 合并公共 SQL 时，检查表名、字段名、状态枚举、索引和菜单权限是否和 [spec.md](./spec.md) 一致。
